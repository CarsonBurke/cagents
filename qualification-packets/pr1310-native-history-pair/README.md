# PR1310 finite native History interaction source

**SOURCE PREPARATION ONLY. Not a usable native controller.** There is no supplied
original-root implementation, execution grant, generated data, binary, native
frame, performance measurement or UX approval. Running `history_driver.py`
refuses with `ROOT_INTERFACE_UNSUPPLIED` before any native import or operation.
No command in this packet launches the application or requests a resource lane.

The user's task is to find an old commit by message, author or SHA, understand a
bounded search, inspect its immutable file, refine/clear the search and page
ordinary History. Before has ordinary History and inspection. After adds the
query field and explicit Enter submission, optional full-SHA resolution combined
with literal matching, and an honest incomplete-search caption with no pager.
Refine is caption text, not a button. A new submission clears rows/detail; this
packet does not require their preservation across a new query.

`observations.py` binds bytes from a future, actually generated `fixture.json`
and commit index to the exact public builder. It validates manifest/index hashes,
cardinalities, sequence, parents, OIDs and expected immutable content. These are
data checks, not a Git/object or filesystem-custody certificate. No data has been
generated. The Root16 DATA delivery is an immutable specification, not a completed
fixture or runtime admission.

`history_driver.py` implements real pyatspi traversal/discovery and xdotool native
input methods against an explicitly missing original-owner interface. It never
calls EditableText.setText, synthesizes an App message, creates Git outcomes,
uses a provider, reads a clipboard or controls processes. The owner must supply
actual pyatspi/PIL modules only after private endpoint admission. AX `grabFocus`
is disclosed when used to set up Enter activation; it is not Tab-navigation
proof. Input is sent once; only read-only observations poll. Unavailable,
ambiguous, clipped or incomplete AX targets stop with HOLD instead of guessed
coordinates or a fake action.

`run_current_dataset` is finite interaction source for one already admitted live
root, not a launcher. It selects wide 1440×900 and narrow 900×700 viewports,
observes 200 initial rows, hover, keyboard and real scroll, opens a commit and
`inspection.txt`, returns through History, and on small401 requests pages
200→400→401. After then enters message/author/late/no-match/full-SHA/refine/clear
queries and presses real Enter. Unborn has its own real notice. Each new root
must use the same independently bound dataset and checkpoint as its paired arm.
The original owner must settle one root before starting the next; this method
does not attempt that missing responsibility.

Captures require an owned PID/XID and exact observed client geometry before and
after. Both `import -screen -window <XID>` and direct `import -window <XID>` must
succeed and produce the same planned window dimensions, a nonblank image and
lossless WebP. An arbitrary full desktop image is never compared to a smaller
drawable. No pointer move, focus or geometry repair occurs inside capture.
The raw PNG and its mode/bands/transparency metadata presence/decoded alpha range
are retained. Acceptance requires every decoded alpha sample to be 255 before RGB
nonblank metrics or saving the original image as WebP. No background is invented
and no alpha is silently discarded. This strict source policy does not establish
actual X11 alpha semantics or the appearance of any unobserved app frame.
Renderer requested settings are not observations; the owner still owes a live
PID/log/XID-bound observed backend, theme/scale provenance and an actual frame.
Configured app scale1.0 is separate from any unmeasured internal native factor.
