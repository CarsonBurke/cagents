This implements the real per-arm worker that was missing between the existing
`NativeHistoryOwner` and `HistoryDriver`. It does not implement or authorize the
original C controller. No module, function, builder, build, tool, native call or
test was executed in this source preparation. All runtime gates remain UNRUN.

The original future parent selects its pinned physical Python with `-I -B`,
retains that worker's original `Popen` and pidfd, and passes the original absolute
whole deadline (at most the original 2400 seconds). `--packet-sha256` and
`--worker-sha256` bind immutable bytes; these arguments provide no authorization.
One worker handles only one arm. Before must terminate with verified physical
closure before the parent builds or admits After against the same warm C target.
Each worker has a separate immutable-input cache; it never repins changing target
artifacts in an already-open owner.

The worker loads the exact b756 owner/driver/observations and d9ee custody bytes.
It retains the original owner before desktop preparation, then adopts only the
six private XDG/TMP and four endpoint values returned by
`prepare_private_desktop()`. Only afterward does it import actual `pyatspi` and
`PIL.Image`, under the unchanged original deadline. It neither changes nor logs
the worker's original HOME, CODEX_HOME or opaque authority values. Existing normal
application pre-main account-selection detachment still applies inside the app;
this is no whole-app HOME-access or natural-startup audit.

For small, large and unborn in order, the worker reads the pinned real builder
manifest/index bytes, constructs the actual `Fixture`, and calls the actual
`HistoryDriver(...).run_current_dataset()`. The existing owner launches
`scripts/run-development --browserless`, including its three isolated matched
build commands. No direct-binary path or mocked native module is supplied. The
owner requires genuine prebuilt matched artifact pins and original build evidence
before launching that runner. Any runner replacement of those immutable inputs
remains a refusal, not permission to repin. There is no runner build-only option.

After each generation it requests normal native close and collects
`history_application_outcome(binding)`. This is RAWFACTS with
`UNKNOWN_PENDING_EXTERNAL_APPLICATION_REVIEW`, even after a known runner zero.
Unknown UI status stays null. The final original worker stdout contains raw
generation facts, the owner's settlement snapshot and its original event ledger.
The parent's original worker wait/pidfd terminal is a separate required writer
and process-completion observation. Worker exit zero means only that the finite
method returned without its own latched failure; it is not native, UX,
application, physical-C-return or logical-allocation acceptance.

On incomplete/ambiguous owner settlement, the worker emits a bounded negative
record if possible and retains its owner and original resources without new
work. It does not detach, find or kill arbitrary PIDs, retry closes or create a
replacement supervisor. The original parent must retain its own known worker
and descendant custody. No signal handler converts cancellation into success.
