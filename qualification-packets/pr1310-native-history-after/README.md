# PR1310 native History fixture source

This adds an **After-only, uncompiled and unrun** development fixture on published
`08bafae7fc2c3c89ecc07b3c831af5e9eb80f103` (product feature parent
`efa9288b3fd79a7214307a11b1c6d50c6cde3630`). It is not a native result or a
natural-startup, account, daemon, provider, IPC, save, migration or shutdown test.
No generated Git dataset, native controller or execution grant accompanies it.
The original builder and existing latency fixtures are unchanged.

## Future launch contract

After separate resource/User admission and matched-executable qualification,
use the ordinary browserless development runner. Its `development,ui` feature
selection includes this leaf without `latency-harness` or a feature override.
The registered original supervisor must preserve literal inherited HOME,
CODEX_HOME, PATH and opaque authority when launching the process. This launcher
requirement does not promise that every variable survives normal app startup:
`cagents-ui::main_with_before_start` still calls the existing
`account::detach_inherited_selections` before fixture validation. That policy
can remove CODEX_HOME and other provider-home variables when their values match
the exact inherited-selection marker or the managed
`accounts/<provider>/<UUID>` namespace shape; it always removes
`CAGENTS_ACCOUNT_HOMES`. This fixture adds no environment scrubbing, changes no
value/account/profile/model/authority policy, and does not force a variable's
presence or absence to satisfy admission. Only independently admitted private
application XDG/TMP state may be provisioned by the original owner. This is
neither a whole-application HOME-access audit nor natural-startup qualification.

Supply both explicit selectors to the future app process:

- `CAGENTS_DEVELOPMENT_HISTORY_FIXTURE`: the published builder's final absolute
  `fixture.json` under its fresh owned 0700 direct `/tmp` or `/var/tmp` child,
  named `pr1310-native-fixture-<suffix>`.
- `CAGENTS_DEVELOPMENT_HISTORY_DATASET`: exactly `small`, `large` or `unborn`.

The schema is `pr1310-public-git-fixture-v1`. The builder SHA is checked against
its compiled exact source bytes; the declared feature pair is
`a3221af83d56663f0dcbef90f67b30ad6d9fe53d` to
`efa9288b3fd79a7214307a11b1c6d50c6cde3630`. The leaf requires the completion
status, canonical owned non-symlink roots, a bounded regular manifest, a real
owned `.git` directory, and the selected expected branch/count/HEAD shape.
`BUILDING.json` is intentionally retained by the builder and is not treated as
failure when the final manifest exists. The ordinary first Git snapshot must
report the manifest's HEAD (including None for unborn); a mismatch stops the
fixture with an explicit diagnostic, rather than hiding a completion or
inventing a read error. Root/repository identities are rechecked at install.
This is a finite fixture path check, not a new filesystem isolation layer;
original supervisor custody and independent builder/data evidence remain
necessary. No Git workload or helper is executed by context validation.

Missing/partial/invalid selectors, conflicting CAGENTS fixture/latency settings,
inherited GIT_* options and nondefault window/device/source arguments refuse
this route. Absence of both selectors reads no fixture files and preserves
ordinary startup. The fixture's conflict checks remove no environment variable
to make a refusal pass; the earlier normal account-selection detachment above
still applies unchanged.

## Actual source route

The opt-in binary branch precedes device preparation, staged execution, window
lease, SessionRuntime, activation listener and daemon preparation. Both routes
use the same factored native COSMIC window/settings/scale construction. The
fixture bypasses operational startup deliberately; the ordinary route keeps
its lease/listener alive while the shared native window runs.

The synthetic fixed project/worktree/workspace IDs only identify the chosen
public dataset. Bootstrap has no cards, session or settings writer. Installation
selects that one descriptor, opens the real Changes/History view, sets dark
style, UI scale 1.0, sidebar 320 and inspector 480, and returns the existing
`source_control_snapshot_task`. Actual window events replace the initial size
estimate. No query, Enter, completion, row, Limited result or error is injected.
`load_pending_history` starts the ordinary first page after the real snapshot.
The real model/reducer/read futures supply each subsequent outcome.

Initialization skips this mode's prune/measurement setup, account/update
installation constructors, hosted/model observers and the operational initial
Task batch. The existing latency benchmark modules and opt-in remain unchanged.
A finite allowlist retains the original App match arms for real snapshots,
History pages, commit details, branch read completions and immutable diff reads,
plus native geometry/layout. It skips the operational update prologue/postlude.
Widget callbacks still come from the actual widgets. Search draft, actual
submit, clear-and-submit, pager, retained-row detail, return-to-list and immutable
file inspection use the existing handlers and guards. Read-only diff scrolling,
folds, next/previous change and split mode are admitted. Other repository edits,
mutations, external launch, global shortcuts, focus-triggered account work and
all provider/session/daemon messages are refused. Resize persistence is dropped;
settings and workspace storage are absent. Normal global Tab/Escape/shortcut
behavior is not qualified by this route. Iced may still handle widget-local
focus/input; actual native evidence must establish what is reachable.

Subscriptions contain native size/scale/edge/close events and necessary native
animation frames only. No periodic refresh, account, Git watcher, terminal,
model, activation, LSP, automation or provider stream is installed. Git futures
return their original typed completion messages directly. Opening an immutable
file uses the original real repository/diff reader and read-only basis;
language servers and editor auto-save are disabled in fixture settings.
A fixture window close exits this native workload only. Normal close/save
settlement is not exercised. The ordinary Drop path remains unchanged;
settings writes refuse before default-path lookup because write-blocked is true,
and no SessionRuntime or LSP/terminal process exists to settle.

## Appearance state observer source successor

This successor merges official main
`4429728a1f179ea7f7eaca9667156553209a46ac` equally into the two native arms
(only host/state.rs and host/chat/retained_actor_tests.rs, exact official blobs).
The original feature/fixture heads are preserved. These are new comparison
source revisions; no earlier source review, executable or runtime result is
transferred to them.

A development-only call at the start of the real main-window App::view reads
one cosmic::theme::active snapshot and Core::scale_factor, the exact source of
Shell::scale_factor. It reports the bounded actual theme class, dark/high-contrast
flags and exact ThemeType::Dark class, without using configured preferences or
the queued appearance Task as completion. Custom/System classes carry no exact
palette identity claim. A private observer targets the allocated Core main ID,
but emits nothing until an original matching Window::Opened event is received.
That iced window ID is not an OS drawable/XID or a compositor mapping receipt.

The existing fixture subscription observes original event_window before mapping
to the unchanged geometry messages. Native scale begins None. After the original
matching Window::Opened, the fixture's existing update tail may issue one real
window::scale_factor(original_id) Task. The existing intercepted
StartupWindowOpened message also checks the same latch, without entering the
normal startup handshake. The query callback is bound to the observer UUID,
original window ID, Opened generation, request UUID and native-scale generation.
A finite positive reply is accepted only while that exact request is pending
and the original window remains open; invalid or missing replies stay unknown.
No retry or configured/initialized/default scale supplies an observation.

The patched iced-runtime Task sends GetScaleFactor for that ID; the patched
iced-winit handler reads window.raw.scale_factor() and replies only if that
window exists. This is read-only query support, not proof that the Task executes
or replies. A later actual Rescaled event supersedes an in-flight query and
keeps its own provenance, even when its numeric value equals a prior query.
Closed, foreign, replaced-observer and obsolete request/generation callbacks
cannot set native scale. The log and its dedup key retain window-open generation,
query-versus-Rescaled provenance, accepted native generation and query request
UUID when applicable. An allocated Core ID/StartupWindowOpened alone still does
not establish Opened proof. No atomic scale/present/compositor guarantee is made.
Two owning reducer guard parents are authored, uncompiled and UNRUN; they do not
exercise the native API or qualify a window, factor, callback or capture.

Target `cagents::native_history` emits bounded `appearance_json` records, version 1,
record kind `history-native-appearance`: original UI PID, opened iced window ID,
observer UUID/generation, actual product version, named compile-time fixture/App/
bin source byte digests, original validated manifest digest/dataset, actual
applied theme/UI scale, optional native scale and its event generation, plus
bounded actual workspace/source/history state. Source digests hash literal
compile-time included bytes; no expected hash/current-head value is hardcoded
inside its own input, and they are not a whole-product or binary certificate.
The external frozen receipt supplies exact hashes for later comparison.

Repeated views with the same observed state emit no new record. Records exclude
per-frame camera/scroll positions, are capped at 4096 bytes and 256 state changes,
and stop with one bounded diagnostic on limits/serialization failure. Actual
recovered original UI log bytes are still required; tracing may be filtered or
its sink unavailable. The record is view-time state readback, not paint/present,
renderer, authority or logging-delivery acknowledgement. No new timer, synthetic
Frame, selector, command-file control, App field or ordinary Message variant is
added. The native owner still owns controller/parser/input/captures and genuine
resource/User admission. All matched binaries, native scale events, frames,
Before/After comparisons, UX and performance remain NULL/UNRUN.
