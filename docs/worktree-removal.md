# Removing a worktree

Choose **Delete worktree** from its sidebar menu. The dialog reads current file and commit safety, then checks it again before removing anything. Open sessions close only after confirmation. If an agent is working in the worktree, confirm the separate interruption warning, which names the number of working agents. A changed count requires fresh confirmation.

**Delete branch too** runs Git's safe branch deletion after the worktree has been removed. It starts enabled only when a matching PR merged at the exact commit currently checked out, in the same source repository. Otherwise it starts disabled. A branch checked out elsewhere cannot be deleted. If the branch is unmerged, the worktree is removed but the branch remains; a second dialog offers **Keep branch** or **Force delete branch**. The force confirmation is bound to the commit shown and refuses if the branch advanced or became checked out. Refusing branch deletion never repeats the worktree removal.

A leftover `cagents:<operation>` lock offers **Unlock and delete** only when its known creation has durably settled, its worktree administrative identity still matches, and its original process lease is free. The proof is repeated before unlocking. An active operation, missing or changed receipt, different process lease, or foreign lock remains blocked. Unlock those through the owning tool or inspect them in Git. Startup recovery does not automatically remove these locks.

With automatic cleanup enabled, a merged worktree that stays shows a quiet **Kept** label. Hover for the full reason, such as an open session, working agent, ignored user data or uncertain ownership. Refused checks do not flash **Deleting**. Daemon refusals wait at least 30 seconds before another attempt; a local pane or session becoming eligible can release its local refusal immediately. Unrelated sessions in other worktrees do not by themselves prevent cleanup, but unknown process ownership still does.
